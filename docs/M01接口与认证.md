# M01 接口、公共契约与企业认证接入

依据 PRD V1.5 FR-01、第 2/7/8 章和项目规划 M01。下述认证接口已实现；公共消息、任务、证据、快照等 Schema 是后续模块的权威结构，不代表对应业务接口已开放。

## 已实现接口

| 方法 / 路径 | 行为 |
| --- | --- |
| GET /auth/login | 303 跳转配置的认证中心；生成 5 分钟有效、绑定当前浏览器的 state/nonce/PKCE 请求。服务不可用时转到可重试的回调失败页。 |
| GET /auth/callback | 校验 state、浏览器、issuer、一次性状态，再交换授权码并验证 ID Token；成功设会话 Cookie 并 303 跳转 `/auth/complete`，失败不创建新登录态。 |
| GET /auth/me | 校验数据库会话、到期、撤销及用户状态；返回当前用户与 CSRF token，不返回 IdP access_token/id_token 或密钥。 |
| POST /auth/logout | 校验 Origin 和 X-CSRF-Token，持久化撤销本系统会话、清 Cookie，303 回登录页；不退出企业认证中心其他应用。 |
| GET /health/live、/health/ready | 公开运维探针；不含业务资料、凭证或版本细节。ready 检查数据库迁移就绪，失败为 503。 |

`/auth/me` 示例（示例值不可用于登录）：

```json
{"id":"1","external_user_id":"[\"https://localhost:9443\",\"1\"]","username":"analyst_demo","display_name":"分析用户","role":"analyst","status":"active","csrf_token":"<per-session-csrf>","expires_at":"2026-10-23T12:00:00Z"}
```

会话使用 256 位随机不透明 Cookie；数据库仅保存 SHA-256。固定 8 小时，不因访问续期；`HttpOnly; Secure; SameSite=Lax; Path=/`。登录临时 Cookie 5 分钟且限定 `/auth`。CSRF token 使用主密钥和会话值派生，写操作同时核对 Origin。时间保存为 UTC 带时区值，展示基准 Asia/Shanghai。

外部身份为紧凑 JSON `[issuer, sub]`，整体唯一；不同认证中心的相同 sub 不会绑定同一用户。只允许显式映射至 analyst/admin，未映射拒绝登录，不默认提权。外部资料更新不覆盖本地 `disabled`。每个 HTTP 请求重新校验本地用户状态，停用立即拒绝；恢复不删除历史。M04 必须复用该校验，并在最迟 30 秒内关闭已有 WS。

错误统一含 `code/message/request_id`，不回显无效请求体或令牌。当前主要错误：401 UNAUTHENTICATED/SESSION_EXPIRED；403 ACCOUNT_DISABLED/FORBIDDEN/CSRF_INVALID；404 RESOURCE_NOT_FOUND；400 INVALID_REQUEST；413 REQUEST_TOO_LARGE；503 DEPENDENCY_UNAVAILABLE。回调错误由固定 `AUTH_CALLBACK_INVALID/AUTH_PROVIDER_INVALID/AUTH_PROVIDER_UNAVAILABLE/AUTH_ROLE_UNMAPPED/ACCOUNT_DISABLED` 映射为中文页，随后移除地址栏错误参数。请求日志不记录 query、Cookie、授权头或请求体；持久审计补充 login_succeeded/logout_succeeded，通用事件由公共 audit 函数脱敏后随调用事务提交。

## 独立认证服务

进程 `uvicorn demo_auth.main:app` 独立运行；使用持久 PostgreSQL 的 `demo_*` 表保存身份、授权交互、一次性授权码和访问令牌摘要。它与应用同用项目 PostgreSQL 实例，以单独表持久化；协议调用经过独立 HTTP/HTTPS 进程，应用不读取演示密码，也不直接信任前端身份。没有引入额外 SQLite/Redis 服务。

OIDC discovery、JWKS、`/authorize`、`/token`、`/userinfo` 均可用。授权页校验真实 PBKDF2-SHA256 密码；每交互最多 5 次失败，5 分钟到期；授权码 60 秒、单次使用，绑定 client、redirect_uri、PKCE S256。客户端使用 HTTP Basic；ID Token 使用持久 RSA 私钥 RS256 签名，access token 与 ID Token 5 分钟有效。账号初始值来自私有文件，启动只插入缺失账号，重启不重置停用或密码。

浏览器表单要求同源 Origin 与随机 CSRF。Referrer-Policy=strict-origin，避免授权查询参数出现在 Referer；CSP form-action 只允许认证站点和注册的应用 origin，以便合法 303 回调。客户端密钥使用 Fernet 主密钥加密保存；DB 会话、授权码、访问令牌和 state 都以摘要保存，PKCE verifier 加密。

## 企业 OIDC 替换

当前支持 OIDC Authorization Code + PKCE S256、Discovery/JWKS、RS256 ID Token、`client_secret_basic`；暂未承诺 SAML、隐式模式、任意签名算法或非标准厂商参数。

1. 在企业认证平台登记保密 Web 客户端，回调为 `https://<应用地址>/auth/callback`，scope 为 `openid profile`，启用授权码与 PKCE S256。
2. 修改项目私有 `.env` 的 `BA_PUBLIC_URL`、`BA_ISSUER_URL`、`BA_ISSUER_INTERNAL_URL`、`BA_CLIENT_ID`、`BA_ROLE_CLAIM`、`BA_ROLE_MAPPING`；public URL 是 origin，issuer 可包含 realm/租户路径。直接企业接入时 internal URL 设置为相同 issuer；容器演示模式才通过可信容器网络重写后端请求地址。
3. 设置 CA 文件（企业 CA 时配置 BA_CA_FILE），保持 TLS 校验；Discovery 的 issuer 必须完全一致。授权 endpoint 必须属于 issuer 的 HTTPS origin，token/JWKS 按受信任元数据访问。
4. 在本机终端执行以下命令安全替换客户端密钥，不将明文放进命令行、仓库或文档：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'backend'
uv run --locked python -m app.credentials
```

5. 重启应用后验证授权、角色、过期和停用。角色声明支持字符串或字符串列表，例如 `BA_ROLE_CLAIM=roles`、`BA_ROLE_MAPPING={"business_analyst":"analyst","system_admin":"admin"}`。本地 user status 始终优先；不自动授予管理员跨用户数据访问能力。

当前未获得真实企业平台注册信息，真实企业平台的兼容性联调仍待提供环境；本模块已验证的是上述标准协议与独立演示 IdP。

## 公共结构与后续模块约束

[schemas.json](./contracts/schemas.json) 与前端 `contracts.ts` 均由后端 Schema 导出。覆盖身份、错误、发送请求、会话/历史、附件快照、工具输入引用与产物、七字段证据、三类 locator、任务快照及 9 类任务事件。保留 JSONB 原字段和空值；对外 ID 是非空字符串；数据库主键为 BIGINT。表结构含原有十表、data_sources 及认证内部表，初始版本和补充完整性迁移为 0001_m01/0002_m01。后续变更新增迁移，不能修改已部署迁移或用删卷重建代替升级。

M02 负责 runtime/runtime_bundle 的完整配置版本 1 初始化及发布协议；M01 仅提供结构和数据库约束，不提前建立第二份可写运行配置。data_sources 的目标/database/schema 受不可变触发器保护。M03—M06 复用 current_session/admin_user/owned_conversation；管理员也经过相同业务归属检查，找不到与越权统一 404。

分页统一 items/next_cursor；消息历史额外固定 snapshot_max_seq_no，游标携带同一会话与排他 before_seq_no，默认 50、上限 100。M01 提供 Schema，分页查询由 M03 实现。消息角色 user/assistant/tool，类型 user_input/assistant_text/tool_call；状态和产物读取可用性均不在前端猜测。

七字段证据及三类定位符合 PRD 5.1；input_refs 使用 `{type:"attachment",attachment_id}`、`{type:"evidence",task_id,evidence_id}`、`{type:"output",task_id,output_id}`，字段按类型成套校验。retention_kind 为 input_copy/derived，由可信服务登记；读取的 available/unavailable_reason 不改变生成时定位，复制/导出保留生成时来源状态，当前可用性另行标识。路径是任务 output 内相对路径，禁止绝对路径、穿越和 NUL；实际授权访问及保留分类在 M03/M05/M06 落实。

连接控制帧必须含 type=subscription_ready、conversation_id、created_at，禁止携带 task_id/event_id。9 类任务事件共有 type/event_id/conversation_id/task_id/created_at，按 PRD 8.4 补齐各类数据。任务快照共有状态、结果关联、全部本任务消息/工具、双格式导出及 last_event_id；M04 实现一致性读取与订阅后恢复。源可用、清理、解析、任务和导出状态枚举均在共享结构/模型中固定，业务状态迁移在主责模块实现。

请求指纹固定夹具见 [request-fingerprints.json](../backend/tests/fixtures/request-fingerprints.json)。规范化字段顺序为 content、data_source_id、task_kind、attachment_ids；content 去首尾空白，task_kind 默认 analysis，附件默认 [] 并按字符串 Unicode 码点排序。重复附件 ID 在基本字段校验时拒绝，不做 Unicode 归一化；紧凑 UTF-8 JSON 的 SHA-256 由服务端生成。`client_request_id` 为 1—128 位 ASCII 字母数字、短横线或下划线；不能以客户端摘要代替校验。提交幂等事务与优先级由 M04 实现。token 计数、表格保真与两条演示的实际夹具分别由 M05/M03/M02 交付。
