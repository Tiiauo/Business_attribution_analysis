# M04 任务与实时通信

M04 模块验收通过。发送、队列、取消、持久化事件、断线恢复和附件接受事务已完成；导出物理文件由 M06 验收。

`scripts/start-dev.ps1` 同时启动 API 与独立 `python -m app.worker`。API 不调用 Docker；worker 通过 PostgreSQL 会话级 advisory lock 保证同库一个调度者，任务队列落库。

| 接口 | 行为 |
| --- | --- |
| POST /api/chat/send | conversation_id、data_source_id、client_request_id、content、task_kind（默认 analysis）、attachment_ids（默认 []）；原子创建消息、任务、自动标题、源绑定及附件首次使用关系 |
| POST /api/tasks/{id}/cancel | queued 直接取消；running 保存首次取消时间，实际执行停止后才终态；重复请求不覆盖首次时间 |
| GET /api/tasks/{id} | REPEATABLE READ 下返回消息、工具、状态、结果ID、配置版本、导出状态和 last_event_id |
| POST /api/chat/ws-token | Cookie、Origin、CSRF 校验；60秒单次令牌，数据库只保存摘要，绑定用户和会话 |
| WS /api/chat/ws/chat | 先安装订阅再发 subscription_ready；连接中每5秒重新验证账户/会话 |
| GET /api/results/{task_id} | 本人成功结果；其他状态分别 RESULT_NOT_READY/TASK_FAILED/TASK_CANCELLED，成功缺记录为 RESULT_MISSING |

同请求ID与规范化指纹一致时返回原任务当前状态，匹配重试跳过归档/源停用等可变条件；异内容为 IDEMPOTENCY_CONFLICT。固定夹具沿用 request-fingerprints.json。同会话一个未结束任务，全局最多三个 running，按接受时间和ID启动；启动时重新检查账户、会话、有效源与模型，保存配置版本及引用快照。取消确认前仍占位。

助手消息先保存再通知，增量、工具状态和游标在同事务提交，PostgreSQL NOTIFY 在提交后分发。工具按调用ID区分；失败/取消保留前缀。模型内部推理链不展示或记录。worker 启动先清理本数据库标签下旧隔离容器/卷，再明确终止遗留 running，queued 保留，不重跑旧运行任务；清理未确认则不释放执行槽。

前端先订阅再读取历史与一致快照，按任务分别维护游标，缓冲增量依序处理，缺号/缺消息回读快照；恢复与5秒可见补偿共用串行同步。切换会话、结果选择及低游标保护防止旧响应覆盖。网络错误不改写任务终态，不自动重发问题。未发送草稿仅存当前标签页 sessionStorage，按用户和会话隔离，接受后删除；不缓存密钥或历史。提交不确定时用原请求ID重试，主动重新分析用新ID。

每轮附件由 M03 选择器显式提交，接受事务保存快照并绑定首次使用消息；排队启动时重新校验账户、会话和有效源。最终报告显式提交，固定 up_to_seq_no/source_task_ids/incomplete_task_ids，禁止新附件和重新取数。
