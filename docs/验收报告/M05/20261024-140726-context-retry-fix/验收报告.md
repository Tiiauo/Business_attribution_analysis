## 原因与修复

原任务36采用4096响应保留量，输出恰好达到4096后截断。任务37已改为16384，但两次结构/证据校验失败的完整草稿仍被继续加入后续请求，导致输入膨胀并触发102400窗口保护。日志还显示模型复制长SQL定位/摘录时改写了内容，或省略source_type/source_name，严格证据校验持续拒绝。

修复内容：

1. 校验拒绝的完整提交参数在下一次请求中省略，保留调用ID、错误和完整重提提示；登记证据、工具记录及已保存过程正文不删。
2. 模型内部提交仅包含证据ID、支撑说明和置信度，后端从本任务/允许历史登记记录补齐原始来源，再统一执行原七字段校验和证据追踪。对外API、前端契约不变；未知ID、夹带来源字段、重复证据及提高置信均拒绝。
3. 16轮总交互中最多12轮探索，最后4轮仅提供结果提交和结构纠正；依据不足时如实说明缺口，不伪造完成或放宽输入窗口、权限和SQL边界。
4. 开发样例库旧mobile/desktop标签同步为Windows/macOS；全部25表行数不变，不清库、不改已有记录的数值基准。见 [同步记录](证据/development-sample-sync.json)。
