# M02 配置、数据源与日志

基线：PRD V1.5，FR-05/08/09，AC-17/19/20/25/29/35/41/42/52/58 的 M02 分项。登录与部署沿用 README。会话、附件、真实分析和报告现已由M03—M06接通，集成验收见M07记录。

## 管理操作

管理员登录后进入“管理中心”。五个页签分别维护配置总览、认证与模型、数据源、工具与资源、脱敏日志。普通用户无管理权限。

1. 读取最新版本，编辑配置或数据源，保存草稿。所有修改携带 `expected_version=edit_version`；同版本并发修改只有一个成功。
2. 对数据源执行“测试连接”，检查连通、绑定范围、只读、跨 schema 拒绝和应用库拒绝。存在草稿时测试草稿，否则测试有效配置；响应 `tested_version` 标明对象。
3. “重载配置”整体验证并发布全部草稿。失败保留有效值和草稿；重启不自动发布。保存成功不代表已经生效。
4. 遇到版本冲突先读取最新配置，对照并核对保留的本地编辑，再使用最新版本保存。凭证输入留空保留，已保存秘密不回显。

认证回调必须与部署 `/auth/callback` 一致；服务 URL 使用 HTTPS。模型表单使用 `base_url`（服务商 API 根地址）、`模型名称`（准确模型 ID）、`api_key`（遮掩显示，清空并保存移除）；还须填写真实上下文窗口。未配置模型仍可登录和管理，不能启动分析。预算与解析阈值整体校验，解析上限不能超出部署容量。

数据源的连接目标、database、schema 一经创建不可修改；更换范围新建 ID。停用/移除先保存草稿，重载后生效；移除保留源身份、历史外键和业务数据。凭证加密存储，运行配置只保存引用。应用数据库不开放给分析账号。

## 接口

写接口须携带登录 Cookie、同源 `Origin` 和 `/auth/me` 返回的 `X-CSRF-Token`。ID 使用字符串。错误统一为 `code/message/request_id`。

| 方法与路径 | 请求及响应 |
| --- | --- |
| GET /api/admin/configs | `active_version/pending_version/edit_version/effective_config/pending_config` |
| POST /api/admin/configs | `{expected_version, changes, credentials?}`，changes 按分组递归合并；credentials 只接受 auth/model；返回配置状态 |
| POST /api/admin/reload | `{expected_version}`；`success` 或无草稿的 `no_change`，返回有效/草稿版本 |
| GET /api/data-sources | 默认只返回已发布启用源；`view=admin` 返回稳定目标及 effective/pending/effective_status |
| POST /api/admin/data-sources | `{expected_version, id?, name, status, connection_target?, database_name?, schema_name?, username?, password?}`；新增须提供完整目标和凭证，编辑不得改变目标 |
| DELETE /api/admin/data-sources/{id} | `{expected_version}`；保存 removed 草稿，不物理删除身份 |
| POST /api/admin/data-sources/{id}/test | 无业务请求体；返回 status/message/checks/tested_version，不发布配置 |
| GET /api/admin/logs | `scope=all/task/system`，level、task_id、operator_id、target_type、target_id、start_time、end_time、cursor、limit；返回 items/next_cursor/checked_at |

日志默认 50、最大 100 条，按时间与 ID 降序稳定分页，下一页原样传回 cursor。时间必须带时区，界面按 Asia/Shanghai 显示。系统日志 task_id 为空，保存真实操作者及目标；任务日志使用真实 task_id。日志脱敏，不包含业务正文、完整提示词或密钥。

常见错误：`CONFIG_VERSION_CONFLICT`（重新核对版本）、`CONFIG_INVALID`（修复草稿）、`DATA_SOURCE_SCOPE_LOCKED`（新建源）、`FORBIDDEN/CSRF_INVALID`（权限或请求校验）、`INVALID_CURSOR`（重新查询）。具体错误码以接口实际返回为准。

## 数据与下游接入

执行 `uv run --locked python -m app.sample_data` 前在 PowerShell 设置 `$env:PYTHONPATH='backend'`。脚本只初始化专用 `ba_demo`，固定种子、日期，重复执行不清库、不叠加、不重置既有凭证；完成后在管理页测试并重载草稿。字典见 [M02数据字典](M02数据字典.md)，逐轮输入见 [两条演示](../samples/demos/README.md)。

M04/M05 在任务开始时调用 `execution_config(db, data_source_id)`，保存返回版本和去密钥快照。源停用或模型未配置会拒绝启动；已取得快照不随重载变化。模块测试验证该快照契约；实际队列、运行客户端与任务落库的集成证据见M07验收报告，后续源码变更仍需复验。

## 分析响应与上下文预算

`context_window_tokens` 是整体上下文窗口，`response_reserved_tokens` 同时作为每次请求的最大响应量并从输入预算扣除。当前deepseek-v4.1-flash演示使用102400窗口和16384响应保留量；其他模型按实际能力配置，不能无上限扩大。修改后须保存草稿并重载，已接受任务仍使用原配置快照。

“模型输出达到响应上限”表示本次输出截断；“工具与证据超过上下文预算”表示后续请求的输入加响应保留量超过本地保护阈值。结果校验重试现会省略无效提交草稿，避免重复累积；16轮总交互中的最后4轮保留给结果提交和校验，不再继续探索；原始工具证据过多时仍须缩小问题或资料范围。失败任务保留失败状态，重试必须用新请求，不自动产生收费调用。
